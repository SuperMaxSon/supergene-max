UI 제작 TODO

프리팹 하나 = 한 줄로 끊어 만들 UI를 전부 세운 판입니다. 컨텐츠 TODO가 기능 단위로 가른 것과 같은 대상을 이 문서는 프리팹 단위로 다시 세고 티어 · 파생 · 현재 상태를 붙였습니다. 두 문서가 겹치면 기능 정의는 컨텐츠 TODO 가, 프리팹 개수와 착수 순서는 이 문서가 정본입니다.

본체는 아래 UI 플로우 맵입니다 — 어느 버튼이 어느 팝업을 여는지를 인게임 / 아웃게임 두 축으로 펼친 판이고, 티어 토글로 층을 켜 가며 봅니다. 표는 그 맵의 명세입니다. 핵심은 화면 번호 개수 ≠ 프리팹 개수라는 것 — 기획서 화면 97개 중 33개는 만들지 않습니다(기준 화면의 상태만 다르거나 공용 템플릿).

우리 판단이 아니라 기획서 §11.1 이 "0층 배경 = 인게임 01 또는 로비 58" 이라고 못 박아 놨습니다. 모든 팝업은 보드 위 아니면 마을 홈 위 둘 중 하나에 뜹니다. 그래서 레인도 이 둘뿐입니다. 가운데 열은 레인이 아니라 이음새입니다 — HUD 3종(아바타 → 67 · 에너지 → 54 · 상점 → 56)은 양쪽에 똑같이 붙어 있어 어느 한쪽에 넣으면 "저쪽 것"으로 읽혀 프리팹을 두 벌 만들게 됩니다. 전역 3종(122 · 123 · 146)도 어느 쪽 소속이 아니라 같은 열에 세웠습니다.

빨간 선 4개가 이 맵의 결론이다

마을 홈의 좌 레일 · 이벤트 진입 은 원문에 "누름 → 각 이벤트" 라고만 적혀 있고 화면 번호가 없습니다. 그래서 라이브옵스 이벤트 4종(라파 12 · 로지 44 · 포피 26 · 장터 23)의 진입 경로가 기획서에 없습니다. 레일 동시 노출은 최대 3인데 이벤트는 5종이라 어떤 이벤트가 어떤 조건으로 레일에 오르는지가 정해져야 구현이 됩니다. T2 를 켜면 보입니다.

진입 경로가 문서화된 것은 64개 중 24개뿐

원문 동작 필드에서 뽑은 간선이 실선 37개입니다. 나머지는 화면 번호 없이 조건으로만 서술돼 있어(에너지 0 · 새 날 전환 · 보드 오브젝트 탭) 점선 37개로 채웠고, 진입 경로 자체가 미정인 빨간 점선 4개를 더해 총 78개입니다(플로우 맵 간선 데이터 실측). 점선은 검증 대상이지 확정이 아닙니다.
