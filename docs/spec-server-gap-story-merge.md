# 기획서 · 프로토콜 규칙 차이 — Rosewood(스토리 머지)

같은 기능을 개발 기획서와 서버 프로토콜이 다르게 적었던 32곳의 지금 상태다. 29곳은 기획서에 결정이 반영돼 두 문서가 같은 규칙을 적는다. 남은 3곳(EV-01 · EV-09 · SH-02)만 어느 쪽으로 맞출지 정해 주면 그 기준으로 구현한다.

- 기획서: 개발 · 밸런스 시트 기획서 v1.25 + 미배포 변경 3건 (v1.25 배포 2026-10-23 · 웹 게시본 2026-11-05 수신) https://atomking0.github.io/supergene-esther/rosewood_dev_spec.html · https://atomking0.github.io/supergene-esther/rosewood_balance_sheet.html
- 프로토콜: merge-story-server `origin/main 1170a96` (2026-11-03) `src/model/type-protocol.ts`. 칸의 `S:줄`은 이 파일의 줄 번호이고, 프로토콜 칸은 원문 요약이라 그대로 믿어도 된다. 「추론」이 붙은 문장은 원문에서 끌어낸 판단이다.
- 상태: 결정 반영 29 · 열림 3 · 미확인 0
- 대조일: 2026-11-05

## 상태
- **결정 반영** (29건): 기획서에 결정이 들어가 두 문서가 같은 규칙을 적는다. 기획서 칸에 절 · 앵커 · 판본을 적었다. 답하지 않는다.
- **열림** (3건): EV-01 · EV-09 · SH-02. 아래 할 일.
- 결정 반영 행의 「남은 문구」는 결정과 맞지 않는 옛 문구나 경로 이름이 기획서 다른 곳에 남은 자리, 또는 그 뒤 프로토콜에만 더해진 내용이다. 규칙 결정은 끝났고 문구 정리만 남았다.

## 할 일
열림 3건만 어느 쪽으로 맞출지 정한다: **기획서**(서버를 고침) · **프로토콜**(기획서를 고침) · **둘 다 수정**(새 규칙) · **보류**(누가 무엇을 정해야 하는지).

- **EV-01** 향초 품평회 완주 뒤 — 동작은 두 문서가 같다(완주 뒤 난이도 재선택 · 1단계부터 · 횟수 제한 없음). 기획서 6.3.1에만 「현재 서버 프로토콜은 회차 최초 참가 때만 난이도를 받고 … 서버 프로토콜에 먼저 반영해야 한다」는 미반영 문단이 남아 있다. 이 문단을 닫아도 되는지 정한다.
- **EV-09** 수집 앨범 · 개인 마일스톤 — 기획서는 앨범 진행 상태와 서버 API(팩 개봉 · 세트 보상 · 교환 상자)를 D29 전에 서버에 추가해야 한다고 적었고, 프로토콜은 앨범 · 마일스톤을 런칭 범위 밖(시트 행만)으로 둔다. 서버 추가 시점과 담당을 정한다.
- **SH-02** 광고 한도 초과 응답 — 기획서는 RATE_LIMITED를 따로 내라고 적었고, 프로토콜은 TABLE_UPDATE_REQUIRED를 내며 RATE_LIMITED 코드가 없다. 어느 쪽으로 맞출지 정한다.

기획서 결정 기록(확정일 · 결정자 · Slack 번호)이 있으면 근거로 쓴다. 없으면 원문 문장을 근거로 쓰되 「결정 기록 없음」을 함께 적는다. 근거가 전혀 없으면 보류. 개발 기획서는 커서 일부 도구가 본문을 다 못 받으니, 필요하면 HTML을 그대로 받아 앵커(예: `#dp-bot-race`)나 절 번호로 찾는다. 결정 반영 내역은 버전 히스토리 v1.24 「서버 프로토콜 차이 32건 결정 반영」(`#build-note-v1-24`)에 있다.
