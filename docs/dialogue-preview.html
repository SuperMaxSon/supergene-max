어디서 온 값인가 등장 곡선은 assets/bundle/chat/clips/chat_show.anim 의 키프레임입니다. 이 클립에는 curve 필드가 하나도 없어 전부 선형 보간이고, 그래서 문서와 엔진의 곡선이 같습니다. 통통 튀는 느낌은 이징이 아니라 키프레임 배치(0 → 0.1667 → 0.3333)에서 나옵니다. 레이아웃·피드 값은 ChatBubbleStoryPresentation.ts 상단 상수, 타이핑·자동넘김은 ChatPresentationConfig.ts, 말풍선 9-slice 는 story_character_text_bubble01.9.json 에서 읽었습니다.

왜 인계 검사를 여기서 하나 과거에 두 번 크게 물렸습니다. trimType 이 auto 로 임포트돼 304×288 프레임이 204×262 로 잘렸고, 잘리는 위치가 프레임마다 달라 재생하면 캐릭터가 튀었습니다 (.meta 270개 되돌림). 그리고 캐스트 이름이 확정 전 이름으로 납품돼 파일 598개를 rename 했습니다. 둘 다 넘기기 전에 이 표를 통과시켰으면 안 났을 일입니다.

내보내기 맞춘 값이 코코스로 건너가는 경로 — 세 갈래로 나뉩니다

왜 세 갈래인가 값이 세 군데에 나뉘어 있기 때문입니다. 설정·레이아웃은 TS 상수라 붙여넣으면 끝이지만, 등장 연출의 알맹이는 코드가 아니라 chat_show.anim 클립 안에 키프레임으로 있습니다. 상수만 넘기면 등장 연출은 반영되지 않습니다. .anim 은 JSON 이라 이 문서가 교체본을 통째로 만들어 줍니다 — 파일을 덮어쓰면 애니메이션 에디터에서 키를 손으로 옮길 일이 없습니다. 대사는 story_dialogue.json 을 그대로 뽑습니다. 리포에 시트→JSON 변환기가 없어서 지금은 사람이 JSON 을 직접 고치고 있는데, 그 자리를 대신합니다.
