5IAP 심사 제출

출처 구분

메뉴 이름은 Meta 현행 문서 그대로. 옛 문서(Phaser 튜토리얼)에만 있는 선행조건 — Production 번들 · 게임 페이지 · 상품 1개 이상이 있어야 getSupportedAPIs() 에 payments.purchaseAsync 가 뜬다 — 은 옛 문서. 결제 API 가 안 보이면 이 셋부터 본다.

결제 흐름누르고 → 결제창 → 서버 검증·지급 → 소비 처리

지금 코드는 isPaymentsAvailable() = !!catalogs 라 카탈로그가 실패하면 복구도 건너뛴다.

실패 코드상황처리
USER_INPUT플레이어 취소조용히 닫기
PENDING_REQUEST결제 진행 중 또 누름버튼 잠금으로 예방
NETWORK_FAILURE네트워크토스트 · 재시도 안내
CLIENT_UNSUPPORTED_OPERATION결제 미지원 클라IAP 숨김 · 광고로
INVALID_PARAMproductID 오류카탈로그 ↔ 코드 대조
PAYMENTS_NOT_INITIALIZEDonReady 전에 호출onReady 대기
INVALID_OPERATION허용 안 되는 호출부팅 순서 확인

취소는 조용히 닫고, 나머지는 전역 토스트 한 줄.

핵심 규칙 하나

서버가 지급을 확정한 다음에만 소비 처리(consume)한다. consume 은 FB 에 "이 구매 처리 끝"을 알리는 것(인게임 재화 사용과 무관). 안 한 구매는 FB 가 들고 있어서 앱이 중간에 꺼져도 다음 부팅에 다시 받는다.
