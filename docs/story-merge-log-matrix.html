등록 방식이 왜 중요한가

이 표를 읽는 법

게임 5칸은 "그 게임이 이 계열을 갖고 있나"만 표시합니다 — 이름·코드가 게임마다 조금씩 다르므로 계열 단위로 묶었습니다. 판정의 핵심은 머지 칸이고, 근거는 항상 호출부가 존재하는가입니다. 스크립트가 리포에 있어도 프리팹이 없으면 도달 불가 = ❌ 또는 🔶로 봤습니다 (ViewManager.load 가 실패하기 때문). 이 구분이 중요한 이유는, 🔶 중 상당수가 프리팹 하나만 만들면 그날 ✅ 로 바뀌는 것이라 작업량 견적이 완전히 다르기 때문입니다.

열 색은 프로젝트 식별색입니다 — 판정 열이 6개라 색 없이는 행을 따라가다 칸을 잃습니다. 판정 대상인 머지를 맨 앞에 두고 테두리로 강조했고, 나머지 5개는 대조군이라 뒤에 붙였습니다. 즉 3열만 읽으면 결론이고, 4~8열은 그 결론의 근거입니다.

회색 18행 — "이미 반영"은 "동작한다"가 아닙니다

회색은 프로토 소스에 BaseLogManager.log(LogType.X, ...) 호출문이 이미 들어가 있다는 뜻입니다(총 153곳 · 그중 도달 가능한 건 30곳). 이 행들은 신규 코드 0줄로, StoryMergeProtoLogManager 에 이벤트명만 등록하면 그대로 발화합니다.

다만 회색 중 3xxx · 4xxx · 950x · 1101x · 80xx 는 호출문이 있는 자리가 플랫폼 어댑터나 프리팹 없는 팝업이라 런타임에 도달하지 않습니다 — 그래서 판정은 여전히 ❌/🔶 입니다. 회색이면서 ✅ 인 것(1000 · 1010 · INTRO_* · 6000 · 6040 · 9000~9300 · NETWORK_*)만이 매핑 등록 즉시 살아나는 구간입니다.

🔶 2100 / 2300 을 재정의해야 하는 이유

5게임 전부 2100_GAMEPLAY_START / 2300_GAMEPLAY_FINISH 를 스테이지 1판 단위로 씁니다. 스토리 머지에는 스테이지가 없고 11노드 선형 순회 1회가 세션 전부입니다. 그대로 쓰면 세션당 1건씩만 찍혀 퍼널 분석이 안 됩니다. 재정의 없이 이름만 재사용하면 BigQuery 에서 다른 게임과 같은 코드로 다른 뜻이 섞입니다 — 대조군에서 이미 발생한 문제입니다.

PLAYTIME 12단이 흰색인 이유

BaseIntro 에 logPlayTime() 호출은 이미 있습니다. 그런데 StoryMergeProtoLogManager 가 이 메서드를 빈 본문으로 override 하고 있어(logLoginComplete() 도 Promise.resolve("{}")) 실제로는 아무것도 발화하지 않습니다. 매핑 등록만으로는 살아나지 않고 override 본문을 대조군에서 이식해야 하므로 흰색으로 분류했습니다.

공통 로그 사용 방법 5게임이 같은 이름으로 쓰는 것만

아래는 대조군 5개가 코드·이름까지 동일하게 쓰는 공통 로그의 사용법입니다. 새 이벤트를 정의하는 것이 아니라 이미 있는 규약을 그대로 따르는 것이 목적이고, 그래야 BigQuery 에서 다른 게임과 같은 쿼리로 비교됩니다. 모든 예시는 solitaire-tripeaks-client main 의 실제 코드입니다.

골격 — 등록 1회, 호출은 정적 메서드

이벤트명 문자열을 호출부에 흩뿌리지 않습니다. LogType enum 하나로 부르고, enum ↔ 이벤트명 매핑은 게임 LogManager 한 곳에서만 등록합니다. 프로토는 이 등록부가 비어 있어 BaseLogManager.log() 가 전부 map miss 로 버려집니다. 

// 1) 등록 — StoryMergeProtoLogManager.initLogManager()
//    super 를 먼저 부른다. base 가 LoginComplete + PLAYTIME 12단을 이미 등록한다.
public initLogManager(logEventHandler: LogEventHandler): void {
    super.initLogManager(logEventHandler);

    this.logEventHandler.registLogEvent(LogType.LoadComplete,     "1010_LOAD_COMPLETE");
    this.logEventHandler.registLogEvent(LogType.GameplayStart,    "2100_GAMEPLAY_START");
    this.logEventHandler.registLogEvent(LogType.GameplayFinish,   "2300_GAMEPLAY_FINISH");
    this.logEventHandler.registLogEvent(LogType.FriendCount,      "6000_FRIEND_COUNT");
    this.logEventHandler.registLogEvent(LogType.SettingLanguage,  "6040_SETTING_LANGUAGE");
    this.logEventHandler.registLogEvent(LogType.ServerError,      "9100_SERVER_ERROR");
    // ...
}

// 2) 호출 — 어디서든 정적 호출. 값은 전부 string 으로 넘긴다.
BaseLogManager.log(LogType.LoadComplete, { time: loadTime });

// 3) 세션 1회성은 once 플래그. 자체 boolean 가드를 새로 만들지 않는다.
BaseLogManager.log(LogType.PlayFirstTouch, undefined, true);

계열별 삽입 지점

"언제 찍는가"는 게임마다 다시 정하지 않습니다 — 대조군이 이미 같은 자리에 꽂아 뒀고, 그 자리가 달라지면 같은 이벤트명인데 분모가 달라져 게임 간 비교가 깨집니다.

파라미터 값은 전부 문자열로
