한 줄 = 코드에서 창 하나로 만들어지는 단위입니다. 같은 창을 공유하는 화면 번호는 한 줄에 묶었고 (예: 149·169 팔기 확인), 라이브옵스와 오퍼는 화면이 전부 0이라 이벤트 하나를 한 줄로 세고 화면 수를 적었습니다. 섹션마다 남은 것만 펼쳐 두고 완료는 접어 뒀고, 남은 것은 기획 준비도가 높은 순(바로 만들 수 있는 것이 위)으로 정렬했습니다. 부분은 창은 있지만 기획서 화면을 다 채우지 못했거나 아직 커밋되지 않은 것입니다. 막대는 초록 → 노랑 → 빨강 → 회색 순으로 완료 · 부분 · 미구현 · 제외 비율입니다.

기획 준비도 게이지

남은 항목마다 화면 · 규칙 · 시트값 · 문구 4축을 채움 1 · 구멍 0.5 · 빠짐 0 으로 매겨 평균을 냈습니다(해당 없는 축은 뺌). 아트와 서버는 이 판단에서 뺐습니다 — 아트는 임시 리소스로 채우고, 서버는 클라 로컬로 먼저 만든다는 전제입니다. 칩 아래 태그는 구멍의 종류입니다: 충돌(문서끼리 어긋남 — 하나만 고르면 끝) · 누락(새로 써야 함) · TBD(기획서가 미정·보류로 표시). 칩 색이 축별 상태이고, 퍼센트 옆 완비 · 공백 · 미완이 판정입니다. 퍼센트는 「얼마나 써 있나」이고 판정은 「지금 막히나」라서 따로 읽습니다 — 출석은 축마다 뭔가 써 있어 50%지만 같은 화면 안에서 숫자가 어긋나 미완입니다. 100% 는 기획서만으로 화면을 끝까지 그릴 수 있다는 뜻입니다.

완료 항목도 기획서와 대조했다

「완료」는 창이 있다는 뜻일 뿐이라, 완료 14개를 열리는 경로 → 원소표 → 규칙 → 시트값 → 문구 순으로 다시 대조했습니다. 접힌 표의 게이지는 원소표 행 중 기획서대로 된 비율이고, 판정은 정합 · 부분 정합 · 불일치입니다. 어긋난 것은 오구현(코드가 기획서와 다르게 동작 — 버그) · 누락(기획서엔 있는데 코드에 없음) · 충돌(기획 문서끼리 어긋나 둘 다 맞출 수 없음)으로 나눴고, 이미 사용자가 정한 이탈(인벤토리 즉시 확장 · 배수 부스터 켬 등)은 의도적 이탈로 따로 적었습니다. 아트·서버는 여기서도 뺐습니다.
