데코 영역 아트 리소스 트리

이전 네이티브 프로젝트에서 데코 영역 아트 리소스를 이런 트리로 공유받았다는 사례입니다. 그렇게 받은 이유는 하나 — 오브젝트마다 상태(state)가 여러 개고, 각 상태에 리소스를 대응시켜야 했기 때문입니다. 망가진 것 → 고쳐진 것, 5단 성장, 완성 디자인 3종 택1이 전부 같은 형태로 흡수됩니다. 신규 웹 프로젝트에 그대로 쓰자는 제안이 아니라, 왜 이 형태가 됐는지 공유가 목적입니다.

이전 프로젝트 사례 임시 — 아트 인계 문서에 합칠 예정 상태별 대응이 이유 마지막 갱신 2026-08-24 14:00

프리팹 트리 영역 1개 = 프리팹 1개 = 로딩 단위 = 아틀라스 단위

이 트리가 된 이유는 상태별 대응입니다. (s = state · 진행 단계와 선택 분기를 모두 포함하는 상태) 오브젝트 하나가 여러 상태를 가지고, 상태마다 이미지 장수·연출이 달라서 상태를 노드로 만들고 그 안에 리소스를 넣는 형태가 됐습니다. 오브젝트 유형이 여러 가지라 트리 하나로는 부족합니다. 영역 루트 조립도 1개와 유형별 샘플 4개를 함께 둡니다 — 유형이 달라도 구조는 전부 같다는 게 요점입니다. 데코 스타일로 보면 배치형 · 수리형 · 건설형 · 선택형 네 가지입니다. 구조는 네 유형이 전부 같습니다: 오브젝트 → 상태 노드 → 이미지·앵커.

필수 · 변경 금지 — 오브젝트 · 상태 (세이브 키 · 값) 필수 — 순서 · 앵커 컴포넌트 이미지 리소스 구조선 · 설명

오브젝트 공통 틀 — 네 샘플이 전부 이 형태입니다

o####                             [DecoObject]  오브젝트 = 미션이 붙는 단위 · 이름이 세이브 키
├── anchor_talk                   말풍선 · 미션 아이콘 생성 좌표 (오브젝트당 1개)
├── anchor_cam                    카메라 이동 목표 좌표 (오브젝트당 1개)
├── s0                            초기 상태 컨테이너 — 진입 연출 없음

├── s1                            [cc.Animation, AnimationResetter]  상태 컨테이너 — 진입 연출 재생
│   ├── (스프라이트 n장)          이 상태의 이미지 리소스
│   └── effect                    진입 연출 — 이름 고정 · 하위는 아트 자유
└── s2 s3 ...                     이후 상태 — s1과 동일 구성 · 분기는 s2_a s2_b s2_c

anchor_cam오브젝트에 1개— 상태별로 두지 않는다
effect상태마다 1개 — 빈 노드
(s0 제외)		연출은 공용 프리팹 · 종류는 테이블 fx
s0필수스프라이트 0~n장 (빈 자리면 0장)
s1 이후 상태1개 이상개수 자유 · 분기 유무
스프라이트—장수 자유 · 파츠 이름 자유
샘플 A~D는 두 가지만 다릅니다

상태 개수와 상태별 스프라이트 장수뿐입니다. 앵커 2종과 s0 필수는 네 샘플 모두 같습니다.

앵커 2종

앵커 붙는 위치 용도 왜 아트가 줘야 하나
anchor_talk 오브젝트에 1개 말풍선 · 미션 아이콘 생성 좌표
"여기에 할 일이 있다" 표시가 뜨는 지점		 오브젝트 상단 기준. 바운딩박스로 계산하면 투명 여백 때문에 틀어짐

이 오브젝트를 보여줄 때 화면 중앙에 둘 지점		 "이 오브젝트를 보여줄 때 화면 중앙에 둘 지점". 주변 여백 구도 판단이 들어가 계산 불가
확인 범위 이전 프로젝트 트리는 기억에 기반한 재구성이며 코드 실측이 아닙니다. 노드 이름은 실제 값을 쓸 수 없어 설명용 표기(o0010 · s0)로 바꿔 적었습니다. 도식은 구조를 보여주기 위한 것이고 실제 아트가 아닙니다. 용량·성능 수치는 이 문서에 없습니다 — 아트 인계 · 이미지 관리 문서를 참고하세요. 이 페이지는 임시이며 정리 후 해당 문서로 합칩니다.
