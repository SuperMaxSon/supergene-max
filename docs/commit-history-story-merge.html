이 표를 이렇게 읽는 이유

앞의 다섯은 git 에서 기계적으로 뽑히는 값이고, 마지막 "작업" 하나만 사람이 씁니다. 문서의 가치는 전부 그 한 줄에 있습니다 — 나머지는 git log 로도 볼 수 있으니까요. 그래서 근거 없는 사유를 채워 넣는 것이 비워 두는 것보다 나쁩니다. 나중에 그 줄을 믿고 판단하게 되기 때문입니다.

묶음(data-group)을 쓰는 경우

하나는 같은 날 같은 주제로 쪼개진 커밋, 하나는 되돌림 쌍입니다. 특히 두 번째가 중요한데, 목록만 보면 되돌린 작업이 "한 일"로 두 번 세어집니다. 묶음 라벨에는 커밋 제목이 아니라 순 효과(결국 무엇이 남았나)를 적습니다. 한 커밋만 있는 주제에는 붙이지 않습니다 — 멤버 1개짜리 묶음은 접힘 한 단계만 늘립니다.

확인 범위 story-merge-proto-client origin/main. 현재 수록 커밋 0건 — 페이지 골격 · 검색 · 영역 필터 · 묶기까지만 준비된 템플릿이다. 미확인 리포에 이미 올라온 다른 작성자의 커밋은 사유 근거(_ignore/history.md)가 없어 수록하지 않았다. 지어낸 사유는 쓰지 않는다. 원본 앞으로의 원본은 story-merge-proto-client/_ignore/history.md 이며, 그 파일이 생기면 이 페이지는 생성물이 된다 — 그때부터는 직접 편집하지 말고 원본을 고친 뒤 다시 생성한다.
