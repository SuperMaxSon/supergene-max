퍼블마 전체 지면 플로우 맵

솔리테어 · 코인 매치 플로우 맵과 같은 두 단 구조입니다. 1단 오픈맵으로 어느 지면이 어느 흐름에 있는지 보고, 2단 지면을 누르면 큰 팝업에 그 지면의 UI 와이어프레임(프리팹을 직접 파싱해 실제 버튼 좌표를 720×1280 세로 화면에 올린 그림)과 버튼별 한 줄 요약이 함께 뜹니다. 와이어프레임의 버튼이나 요약 셀을 누르면 그 자리에서 호출 흐름이 아래로 펼쳐집니다. 맵은 세로 스파인입니다 — 가운데 줄기가 한 판의 진행 순서(부팅 → 진입 라우팅 → 인게임 → 판 종료 후 5단계 → 로비)이고, 왼쪽 레일은 그 단계에서 새어 나가는 길, 오른쪽 레일은 그 단계가 여는 지면입니다. 띠 5개가 세로 눈금이라 위에서 아래로만 훑으면 한 판이 끝납니다. 찾는 게 정해져 있으면 오른쪽 위 검색창(단축키 /)에 메소드명 · 지면 이름 · 프리팹 · 버튼 라벨을 치면 그 지면을 열고 접힘까지 펼쳐서 보여줍니다.

비활성 버튼을 왜 남겼나

프리팹의 _active = false 는 “에디터에 파킹”이 아니라 대개 런타임 조건부 노출입니다. 같은 지면에 활성본이 따로 있을 때만 버렸고 (이번에 0개), 그 핸들러로 갈 길이 이것뿐이면 남겨 점선으로 그립니다. 함부로 버리면 조건부로만 뜨는 버튼이 통째로 사라집니다.

결과 후 플로우 판이 끝난 뒤 무엇이 순서대로 일어나는가

근거는 ViewGame.gameOver() 1732~1845줄 입니다. 위에서 아래로 순서대로 지난다. 맵에서는 이걸 한 줄짜리 진행 칸 5개로 스파인 위에 폈습니다 — 카드 하나의 접힘 표 안에 두면 클릭 없이 보이는 진행 단계가 0이 되기 때문입니다.

칸하는 일
① 부활 제안showPopupRevive() — 놓을 자리가 없어진 시점에 gameOver() 보다 먼저 뜬다(1649줄). 안 하면 gameOver() 로 내려온다
② 정리세이브(SAVE_GAME_DATA · SAVE_DATA_TIME) 삭제 · dynamicDifficulty.updateAfterGame(moveCount). 점수가 500 미만일 때만 플레이 로그 전문을 보낸다
③ 토너먼트 바이럴handleGameOverTournament() — solo/p2p 는 생성 다이얼로그(거절 카운터 게이트), 토너먼트 판이었으면 공유 다이얼로그 + 사일런트 postScore 병행
④ 게임오버 팝업isBestScore 면 PopupGameOverBestScore, 아니면 PopupGameOver. 진행 중 이벤트에 따라 팝업 내용을 세운다
⑤ 두 버튼Home — 가장 먼저 Fbi.switchToContextSolo() 후 로비 / Restart — 컨텍스트를 그대로 두고 showViewGameWithRecommendation(result)

컨텍스트 분기 같은 지면 · 같은 버튼이 상태에 따라 다르게 동작한다

맵을 만들며 확인된 것

부팅이 로비를 건너뛴다 — Intro.moveToNext() 의 기본 경로가 showViewGameWithSoloTournament() 다(Intro.ts:600). 코지·마종·코인매치는 전부 로비로 떨어진다. 그래서 맵의 띠 순서도 인게임 → 사후 → 로비 다.

전면광고 호출부가 3곳뿐 — Fbi.tryShowInterstitialAD 호출부가 3곳이다 — 마종 38 · 코지 27 과 대조된다. 대신 Fbi.createTournament 는 6곳으로 4개 프로젝트 중 가장 많다.

로비 탭 3장인데 홈만 로딩 방식이 다르다 — HomeTab 은 ViewLobby 프리팹 안에 박혀 있고(@property(LobbyTabHome)) tabBundleMap 에 없다. 랭킹·리그만 lobby_tab/ 에서 지연 로드한다(ViewLobby.ts:117~127).

PopupAdBreak 은 프리팹이 없다 — 클래스와 ViewCreator.showPopupAdBreak() 는 있는데 프리팹이 저장소에 없다. 유일한 실호출부(Fbi.ts:592)도 주석 처리돼 있어 현재는 죽은 경로다 — 맵에서 뺐다.

intr_en 빌드는 바이럴을 다음 클릭에 편승시킨다 — 유저 제스처 제약으로 게임오버 시점에 다이얼로그를 못 연다. deferredViralHandler 로 게임오버 팝업의 다음 클릭(Restart/Home)에 붙인다(ViewGame.ts:1824~1828). 유저가 팝업을 안 누르면 발사되지 않는다.

게임오버 팝업이 두 프리팹이다 — 최고점 여부로 PopupGameOverBestScore / PopupGameOver 가 갈리는데 같은 메소드를 받는다. 이벤트 표시를 고칠 때 한쪽만 고치면 최고점 유저에게만 안 보인다.

결제 불가 지역에서 상점 버튼이 침묵한다 — TopCoin.onClickGoldShop · onClickTicketShop 은 isPaymentsAvailable() 이 false 면 토스트도 없이 아무 일도 하지 않는다.

PopupToastError 가 성공 알림에도 쓰인다 — 유저 ID 복사 완료 · 우편 새로고침 완료가 이 팝업으로 나간다. 이름과 쓰임이 어긋나 로그 해석 시 주의가 필요하다.
