토너 클리어 생성 지면 A/B

AOS에서 토너먼트가 붙은 컨텍스트의 판 클리어 지면을 공유에서 생성으로 바꾸면 수락률이 오르는지 보는 A/B입니다. 두 빌드가 같은 기간에 서빙되므로 날짜 교란 없이 대조합니다. AOS 외 OS와 SOLO 컨텍스트는 양쪽 빌드가 동일하므로 분모에서 제외합니다.

A 496 · B 497 AOS 한정 측정 · 09-15~09-18 누적

A/B 정의 무엇과 무엇을 견주는가

군 빌드 토너 컨텍스트 클리어 지면 기존 토너 FB 점수 등록
A 대조군 client_version = 496 공유 (shareAsync) 공유를 수락했을 때만
B 처치군 client_version = 497 생성 (createAsync) 수락과 무관하게 무조건
FB 점수 등록률은 지표에서 뺐다

B 는 지면 수락과 무관하게 postScoreAsync 를 먼저 쏘므로 등록이 오르는 건 설계를 다시 읽은 값이지 처치의 성과가 아닙니다. 게다가 분자 3310 은 토너 컨텍스트에서만 찍혀 A 에는 game_clear_tournament 분이 아예 없어 두 군의 분자 성격이 다릅니다. 배선 검증은 이미 끝났습니다 — 등록 시도가 670 → 1,616 건으로 2.4 배 늘고 성공률은 양쪽 모두 99% 대 (3310 ÷ 3300 = A 99.4% · B 99.7%)입니다.

분모를 좁히는 이유

두 빌드가 갈리는 건 AOS · 토너 있는 컨텍스트 · 판 클리어 세 조건이 모두 맞을 때뿐입니다. iOS·PC와 SOLO 판, 토너 없는 스레드는 A·B가 완전히 같은 코드를 타므로 분모에 넣으면 차이가 희석됩니다. 모든 KPI는 이 조건으로 필터한 뒤 계산합니다.

지면 플로우 어느 칸이 갈리는가

판별은 두 단계입니다. 컨텍스트 타입(SOLO / THREAD)을 먼저 가르고, THREAD일 때만 토너 유무를 한 번 더 조회합니다. A와 B가 갈리는 칸은 파란 칸 하나이고, 나머지 경로는 두 빌드가 동일합니다.
B에서는 FB 점수 등록 칸이 분기 앞으로 나옵니다. A는 등록이 공유 수락에 걸려 있어 거절하면 기록이 남지 않지만, B는 지면을 거절해도 등록이 끝나 있습니다. 대신 수락하면 새 토너로 옮겨가며 친구 컨텍스트가 해제됩니다 — A에서는 공유가 컨텍스트를 건드리지 않아 유지되던 부분입니다.

KPI 판정 지표와 기준

A · 496 공유 지면(대조) · B · 497 생성 지면(처치). 막대 길이는 같은 그룹 안에서만 견줍니다 — 수락률과 잔존율은 단위가 같아도 기대 범위가 달라 한 자로 재면 잔존율 막대가 항상 길어 보입니다. Δ 는 큰 글씨가 상대 증감(%), 작은 글씨가 차이(pp)입니다. 09-17 부터 486 이 빠져 두 빌드가 전량 서빙이고 군 배분도 거의 반반이라, 아래 채택 조건으로 판정할 수 있는 구간입니다. 다만 값은 09-15~오늘 누적이라 09-15~16 배포 초기 구간이 섞여 있습니다.
채택 조건

주 지표 둘 다 B가 앞서고, 가드레일 셋 중 어느 것도 유의하게 나빠지지 않아야 채택합니다. 차이(pp)는 절대값, 상대 증감(%)은 A 대비 비율입니다 — 수락률처럼 모수가 작은 지표는 pp가 작아도 상대 증감이 크게 잡히므로 둘을 같이 봅니다. 수락률만 오르고 판수·잔존이 빠지면 바이럴을 얻고 플레이를 잃은 것이므로 되돌립니다.

집계 시 주의

같은 3100·3110이라도 SOLO 컨텍스트 생성은 position = game_clear, 이번 A/B 대상은 game_clear_tournament로 찍힙니다. B(생성)는 position을 반드시 필터해야 하며, 섞으면 B의 수락률이 기존 SOLO 생성분에 희석됩니다. 반대로 A(공유) 3200·3210에는 position이 아예 없습니다(null) — 같은 필터를 걸면 A가 0으로 사라집니다. 3300계열은 2026-08-19 이전 구간과 의미가 달라 시계열 비교에서 제외합니다.

배너 KPI 496·497 공통 · 09-15~09-18 누적 (09-18 08:58)

막대 트랙 전체가 그 행의 분모입니다 — 오른쪽 열이 100% 에 해당하는 모수입니다. 노출 지속 중위 53초(n 42,390). 실패 구성 색은 미지원 클라이언트 · 재고 없음 · 기타(ADS_FREQUENT_LOAD · RATE_LIMITED · UNKNOWN · NETWORK_FAILURE) 순입니다.
노출 그날 4310 이 있는 유저 · 미노출 같은 날 skip_reason=min_plays_not_met. 미노출군은 최소 판수 미달 코호트라 판수가 구조적으로 낮습니다 — 절대 비교 대신 10110 경계 전후 같은 유저로 확인합니다. 미노출군 866명.
쿼리 A. 배너 퍼널 — 일자 × 빌드 · 사유 분포 
-- 4300 은 판 시작마다 찍힌다. status='true' 가 실제 시도, status='false' 의 skip_reason 이 미노출 사유다.
SELECT
    log_date AS `날짜`,
    client_version AS `빌드`,
    COUNTIF(event = '4300_BANNER_AD_START') AS `판정`,
    COUNTIF(event = '4300_BANNER_AD_START' AND JSON_VALUE(data, '$.status') = 'true') AS `시도`,
    COUNTIF(event = '4310_BANNER_AD_FINISH') AS `노출`,
    COUNTIF(event = '4320_BANNER_AD_ERROR') AS `실패`,
    ROUND(SAFE_DIVIDE(
        COUNTIF(event = '4310_BANNER_AD_FINISH'),
        COUNTIF(event = '4300_BANNER_AD_START' AND JSON_VALUE(data, '$.status') = 'true')
    ) * 100, 1) AS `로드_성공률_pct`,
    COUNT(DISTINCT IF(event = '4310_BANNER_AD_FINISH', player_id, NULL)) AS `노출_유저`
FROM `game-log-359704.raw.solitaire_city_journey`
WHERE log_date BETWEEN '2026-09-15' AND CURRENT_DATE('Asia/Seoul')
    AND event IN ('4300_BANNER_AD_START', '4310_BANNER_AD_FINISH', '4320_BANNER_AD_ERROR')
    AND client_version IN (496, 497)
GROUP BY `날짜`, `빌드`
ORDER BY `날짜`, `빌드`;


-- 미노출(skip_reason)과 실패(error_code)를 한 열에 세운다.
SELECT
    CASE
        WHEN event = '4300_BANNER_AD_START'
            THEN 'skip:' || COALESCE(NULLIF(JSON_VALUE(data, '$.skip_reason'), ''), 'none')
        ELSE 'error:' || COALESCE(NULLIF(JSON_VALUE(data, '$.error_code'), ''), 'UNKNOWN')
    END AS `사유`,
    COUNT(*) AS `횟수`,
    COUNT(DISTINCT player_id) AS `유저수`,
    ROUND(COUNT(*) * 100.0 / SUM(COUNT(*)) OVER (), 1) AS `비중_pct`
FROM `game-log-359704.raw.solitaire_city_journey`
WHERE log_date BETWEEN '2026-09-15' AND CURRENT_DATE('Asia/Seoul')
    AND event IN ('4300_BANNER_AD_START', '4320_BANNER_AD_ERROR')
    AND client_version IN (496, 497)
GROUP BY `사유`
ORDER BY `횟수` DESC;
쿼리 B. 부작용 대조 — 노출군 vs 미노출군 
-- 군은 빌드가 아니라 '그날 배너를 실제로 봤는지'로 가른다(배너는 496·497 공통).
WITH ev AS (
    SELECT
        log_date AS d,
        player_id,
        event,
        JSON_VALUE(data, '$.skip_reason') AS skip_reason,
        JSON_VALUE(data, '$.result') AS result
    FROM `game-log-359704.raw.solitaire_city_journey`
    WHERE log_date BETWEEN '2026-09-15' AND CURRENT_DATE('Asia/Seoul')
        AND client_version IN (496, 497)
        AND event IN (
            '4300_BANNER_AD_START', '4310_BANNER_AD_FINISH',
            '2100_GAMEPLAY_START', '2300_GAMEPLAY_FINISH', '2223_GAMEPLAY_END_SURE_RETRY'
        )
),
grp AS (
    SELECT
        d,
        player_id,
        CASE
            WHEN COUNTIF(event = '4310_BANNER_AD_FINISH') > 0 THEN '1_노출'
            WHEN COUNTIF(event = '4300_BANNER_AD_START' AND skip_reason = 'min_plays_not_met') > 0 THEN '0_미노출'
        END AS grp,
        COUNTIF(event = '2100_GAMEPLAY_START') AS plays,
        COUNTIF(event = '2300_GAMEPLAY_FINISH') AS finishes,
        COUNTIF(event = '2300_GAMEPLAY_FINISH' AND result = 'clear') AS clears,
        COUNTIF(event = '2223_GAMEPLAY_END_SURE_RETRY') AS retries
    FROM ev
    GROUP BY d, player_id
)
SELECT
    d AS `날짜`,
    grp AS `군`,
    COUNT(*) AS `유저수`,
    ROUND(AVG(plays), 2) AS `인당_판수`,
    ROUND(SAFE_DIVIDE(SUM(clears), SUM(finishes)) * 100, 1) AS `판_클리어율_pct`,
    ROUND(SAFE_DIVIDE(SUM(retries), SUM(finishes)) * 100, 1) AS `재시도율_pct`
FROM grp
WHERE grp IS NOT NULL
GROUP BY `날짜`, `군`
ORDER BY `날짜`, `군`;
