이 표를 읽는 법

감정당은 감정 하나를 더 붙일 때 늘어나는 용량(한계비용)입니다. 총량을 감정 수로 나눈 평균이 아닙니다. 프레임 시퀀스는 감정마다 이미지 전체를 새로 저장하니 한계비용 = 감정당 전량이지만, 나머지 둘은 베이스 텍스처를 공유하고 눈·입 변형과 키프레임만 추가하므로 한계비용이 훨씬 작습니다. 그래서 감정이 늘수록 배수가 커집니다 — 이 표의 배수는 고정값이 아닙니다.

프레임 수가 어디에 걸리는지

프레임 수는 프레임 시퀀스에만 곱해집니다. 노드 트랜스폼과 스켈레탈은 프레임이 아니라 키프레임으로 저장하고, 그 사이는 런타임에 보간하기 때문에 애니메이션을 길게 늘려도 용량이 거의 그대로입니다. 실측이 이걸 그대로 보여줍니다 — 솔리테어 루나는 채팅 얼굴보다 프레임 환산이 13배 많은데 용량은 1/12입니다.

비교가 성립하는 이유

puzzle-omg green은 스켈레톤이 320×296으로 채팅 얼굴 304×288과 거의 같은 크기이고, 감정도 4개(angry · beam · happy · mission)로 같습니다. 리그 구성도 같습니다 — 베이스 몸통 하나에 눈·입 변형을 얹는 방식이고, 솔리테어 루나도 head / eyes_front / eyes_up / eyes_close 로 동일한 구조입니다. 반면 루나는 표시 크기가 채팅 얼굴의 1/3 면적이라 원본 용량을 그대로 쓰면 과소평가가 됩니다. 그래서 산출기는 계수를 304×288 로 정규화해 두었습니다.

방식 이름

노드 트랜스폼 애니메이션은 노드 트리로 파츠를 분리하고 cc.Animation 으로 position / scale / angle / opacity 키프레임만 찍는 방식입니다. 솔리테어 루나 클립 7종 전부 spriteFrame 키가 0개인 걸로 확인했습니다. Spine 처럼 보이지만 외부 툴도 런타임도 쓰지 않습니다. “본 애니메이션”은 틀린 이름입니다 — 실제 본이 없고 노드 계층 트랜스폼뿐입니다. 세 방식 중 아래 둘이 컷아웃 애니메이션에 속하고, 프레임 시퀀스는 아닙니다.

확인 범위 프레임 시퀀스 — story-merge-proto-client 워킹트리 assets/bundle/chat/ PNG 272장 · .anim 16종 전수(2026-08-31). 클립 3건이 프레임 수와 어긋나 있습니다 — brett_neutral 은 키 15개로 00016·00017 2장이 미사용, poppy_neutral 은 키 18개로 00001 을 두 번 참조합니다. 루프 길이도 각각 1.000s / 1.200s 로 나머지 1.133s 와 다릅니다. 이 문서의 계수는 PNG 17장 기준이라 해당 건과 무관합니다. 노드 트랜스폼 — solitaire-tripeaks-client 루나(리워드 박스 고양이) 실측. 파츠 텍스처가 1.603 B/px 로 사내에서 압축이 가장 비효율적이어서, 이 계수는 보수적(높게 잡힌) 값입니다. 스켈레탈 — puzzle-omg 5세트가 사내에 존재하는 캐릭터 Spine 전부입니다. 솔리테어 · 코지 · 마종 · 블록블라스트 · 스페이스블라스트는 .atlas 0개이고, 각 리포의 common/ui/SpinePlayerOnEnable.ts 는 붙일 에셋이 없는 템플릿 보일러플레이트입니다. coin-match gold_pig(221 KB)은 감정 표현이 아닌 연출용이라 회귀에서 제외했습니다. 모든 용량은 10진(1 KB = 1,000 B)이며 소스 파일 기준입니다. GPU 텍스처 메모리는 압축이 풀려 별도로 계산해야 합니다 — 채팅 얼굴은 감정당 5.95 MB, 16감정 전체 95.3 MB 입니다.
