이 문서만 읽고 답할 수 있게 만들었다. 아래 표의 항목마다 개발 기획서와 서버 프로토콜이 같은 기능을 다르게 정했다. 「기획서대로 만들면」과 「프로토콜대로 만들면」은 각 문서 원문을 그대로 구현했을 때의 동작이다. 프로토콜 원문은 서버 레포에만 있으므로 이 표의 프로토콜 칸을 원문 요약으로 믿어도 된다(줄 번호는 merge-story-server 64d086e src/model/type-protocol.ts).

할 일 — 항목 ID마다 어느 쪽으로 맞출지 정한다. 기획서 원문을 확인할 수 있으면 해당 절을 열어 근거를 붙인다.

  • 기획서: 기획서가 맞다 → 서버 프로토콜을 기획서대로 고친다
  • 프로토콜: 프로토콜이 맞다 → 기획서를 프로토콜대로 고친다
  • 둘 다 수정: 둘 다 아니다 → 새 규칙을 적는다
  • 보류: 지금 정할 수 없다 → 누가 · 무엇을 정해야 하는지 적는다

SP-로 시작하는 항목은 기획서 안의 두 문장이 서로 다르다. A · B 중 맞는 문장을 고른다.

원칙 — 기획서에 결정 기록(확정일 · 결정자 · Slack 번호)이 있으면 그걸 근거로 쓴다. 근거 없이 추측하지 않는다. 모르면 보류로 답한다.
