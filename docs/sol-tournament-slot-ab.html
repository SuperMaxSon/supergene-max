① 일자 × 빌드 — 슬롯 퍼널 + 가드레일 · 완료 (유저군 축은 ④가 대체)

② 유입 세션 — 버전축 없이 날짜축으로만 · 완료 
-- 수신자의 빌드는 발신자의 처치와 무관하므로 client_version 축을 넣지 않는다.
-- entrypoint_now는 그 유저의 마지막 로그인 블롭이라 1000_LOGIN_COMPLETE로 고정해야 한다.
SELECT
    log_date AS `날짜`,
    JSON_VALUE(entrypoint_now, '$.payload.social') AS `유입경로`,
    COUNT(*)                  AS `세션수`,
    COUNT(DISTINCT player_id) AS `유저수`
FROM `game-log-359704.raw.solitaire_city_journey`
WHERE log_date BETWEEN '2026-08-28' AND CURRENT_DATE()
    AND event   = '1000_LOGIN_COMPLETE'
    AND country = 'US'
    AND JSON_VALUE(entrypoint_now, '$.payload.social') IN ('TOURNAMENT', 'TOURNAMENT_INVITE')
GROUP BY `날짜`, `유입경로`
ORDER BY `날짜`, `유입경로`;
④ 보드 본체 — 일자 × 빌드 × 유저군 · 미수신 
-- 보드의 전체/RU/NRU 탭을 한 번에 채우는 쿼리. ①을 대체한다 —
-- 유저-일은 RU이거나 NRU 둘 중 하나라 두 행을 더하면 '전체'가 그대로 나온다.
-- is_new_device는 로그인 로그(1000)의 data에만 실리므로, has_login과 같은 방식으로
-- 윈도우를 써서 유저-일 전체에 전파해야 다른 이벤트 행에도 유저군이 붙는다.
SELECT
    log_date                    AS `날짜`,
    client_version              AS `빌드`,
    IF(is_nru = 1, 'NRU', 'RU') AS `유저군`,
    COUNT(DISTINCT IF(has_login = 1, player_id, NULL))                   AS `DAU`,
    COUNTIF(event = '2300_GAMEPLAY_FINISH')                              AS `판_종료`,
    COUNTIF(event = '3200_TOURNAMENT_SHARE')                             AS `공유_시도`,
    COUNTIF(event = '3210_TOURNAMENT_SHARE_SUCCESS')                     AS `공유_성공`,
    COUNTIF(event = '3460_MSG_P2P_INVITE'
            AND JSON_VALUE(data, '$.position') = 'tournament_invite')    AS `초대_시도`,
    COUNTIF(event = '3470_MSG_P2P_INVITE_SUCCESS'
            AND JSON_VALUE(data, '$.position') = 'tournament_invite')    AS `초대_성공`,
    COUNTIF(event = '3230_TOURNAMENT_SHARE_SUPPRESSED')                  AS `미노출`,
    COUNTIF(event = '3100_TOURNAMENT_CREATE')                            AS `생성_시도`,
    COUNTIF(event = '3110_TOURNAMENT_CREATE_SUCCESS')                    AS `생성_성공`,
    COUNTIF(event = '4010_INTERSTITIAL_AD_FINISH')                       AS `전면광고`,
    COUNTIF(event = '4210_RV_FINISH')                                    AS `RV`
FROM (
    SELECT
        log_date, player_id, event, data, client_version,
        MAX(IF(event = '1000_LOGIN_COMPLETE', 1, 0))
            OVER (PARTITION BY log_date, player_id) AS has_login,
        MAX(IF(event = '1000_LOGIN_COMPLETE'
               AND JSON_VALUE(data, '$.is_new_device') = 'true', 1, 0))
            OVER (PARTITION BY log_date, player_id) AS is_nru
    FROM `game-log-359704.raw.solitaire_city_journey`
    WHERE log_date BETWEEN '2026-09-03' AND CURRENT_DATE()
        AND country = 'US'
        AND client_version IN (485, 486)
)
GROUP BY `날짜`, `빌드`, `유저군`
ORDER BY `날짜`, `빌드`, `유저군`;
⑤ 판수 분포 — p50 · 빌드 × 유저군 · 미수신 
-- 판 종료 ÷ DAU는 평균이라 헤비 유저 몇 명에 끌린다. 중앙값을 같이 봐야
-- "다수가 더 했나"와 "소수가 많이 했나"가 갈린다. 단위는 유저-일이다.
-- APPROX_QUANTILES는 NULL을 무시하므로 IF(n>0, n, NULL)로 플레이한 유저만 따로 볼 수 있다.
SELECT
    client_version              AS `빌드`,
    IF(is_nru = 1, 'NRU', 'RU') AS `유저군`,
    COUNT(*)                                              AS `유저_일`,
    ROUND(AVG(n), 2)                                      AS `판수_평균`,
    APPROX_QUANTILES(n, 100)[OFFSET(50)]                  AS `판수_p50`,
    APPROX_QUANTILES(n, 100)[OFFSET(75)]                  AS `판수_p75`,
    APPROX_QUANTILES(n, 100)[OFFSET(90)]                  AS `판수_p90`,
    ROUND(COUNTIF(n > 0) * 100.0 / COUNT(*), 1)           AS `플레이유저비율_pct`,
    APPROX_QUANTILES(IF(n > 0, n, NULL), 100)[OFFSET(50)] AS `p50_플레이유저`
FROM (
    SELECT
        log_date, player_id, client_version,
        COUNTIF(event = '2300_GAMEPLAY_FINISH') AS n,
        MAX(IF(event = '1000_LOGIN_COMPLETE'
               AND JSON_VALUE(data, '$.is_new_device') = 'true', 1, 0)) AS is_nru
    FROM `game-log-359704.raw.solitaire_city_journey`
    WHERE log_date BETWEEN '2026-09-03' AND CURRENT_DATE()
        AND country = 'US'
        AND client_version IN (485, 486)
    GROUP BY log_date, player_id, client_version
)
GROUP BY `빌드`, `유저군`
ORDER BY `유저군`, `빌드`;
⑥ D1 리텐션 — 코호트일 × 빌드 × 유저군 · 미수신 
-- 코호트 = 그날 로그인한 유저를 그날의 빌드·유저군으로 묶은 것.
-- 복귀 판정에는 빌드를 걸지 않는다 — 걸면 다음 날의 업데이트를 이탈로 오독한다.
-- ⚠ 486은 9/3부터라 D1을 볼 수 있는 코호트가 9/3 하루뿐이고 복귀일 9/4가 부분 집계다.
--    지금 값은 확정이 아니라 기준선이다 — 완전한 하루가 쌓인 뒤 다시 돌린다.
WITH cohort AS (
    SELECT
        log_date, player_id, client_version,
        MAX(IF(JSON_VALUE(data, '$.is_new_device') = 'true', 1, 0)) AS is_nru
    FROM `game-log-359704.raw.solitaire_city_journey`
    WHERE log_date BETWEEN '2026-09-03' AND CURRENT_DATE()
        AND event   = '1000_LOGIN_COMPLETE'
        AND country = 'US'
        AND client_version IN (485, 486)
    GROUP BY log_date, player_id, client_version
),
ret AS (
    SELECT DISTINCT log_date, player_id
    FROM `game-log-359704.raw.solitaire_city_journey`
    WHERE log_date BETWEEN '2026-09-03' AND CURRENT_DATE()
        AND event   = '1000_LOGIN_COMPLETE'
        AND country = 'US'
)
SELECT
    c.log_date                    AS `코호트일`,
    c.client_version              AS `빌드`,
    IF(c.is_nru = 1, 'NRU', 'RU') AS `유저군`,
    COUNT(DISTINCT c.player_id)                                    AS `코호트`,
    COUNT(DISTINCT IF(r.player_id IS NOT NULL, c.player_id, NULL)) AS `D1_복귀`,
    ROUND(COUNT(DISTINCT IF(r.player_id IS NOT NULL, c.player_id, NULL)) * 100.0
          / COUNT(DISTINCT c.player_id), 1)                        AS `D1_리텐션_pct`
FROM cohort c
LEFT JOIN ret r
    ON r.player_id = c.player_id
   AND r.log_date  = DATE_ADD(c.log_date, INTERVAL 1 DAY)
GROUP BY `코호트일`, `빌드`, `유저군`
ORDER BY `코호트일`, `빌드`, `유저군`;
③ 배정 균형 — 무작위 배정인지 간접 확인 · 미수신 
-- FB가 지역·기기 기준으로 갈랐다면 국가·OS 구성이 어긋나고, 그러면 유저 편향이 남는다.
-- 국가 필터를 일부러 빼서 지역 배정 여부까지 본다.
SELECT
    client_version AS `빌드`,
    country        AS `국가`,
    IFNULL(os, '(null)') AS `OS`,
    COUNT(DISTINCT player_id) AS `유저수`,
    ROUND(COUNT(DISTINCT player_id) * 100.0
          / SUM(COUNT(DISTINCT player_id)) OVER (PARTITION BY client_version), 1) AS `군내_비중_pct`
FROM `game-log-359704.raw.solitaire_city_journey`
WHERE log_date BETWEEN '2026-09-03' AND CURRENT_DATE()
    AND event = '1000_LOGIN_COMPLETE'
    AND client_version IN (485, 486)
GROUP BY `빌드`, `국가`, `OS`
HAVING `유저수` >= 10
ORDER BY `국가`, `OS`, `빌드`;
