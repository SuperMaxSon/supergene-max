485 NRU p50은 09-03 5,149 → 09-04 5,190으로 내려가지 않았습니다. 반면 483은 배포 당일 평균 11,345ms에서 다음 날 7,951ms로 크게 내려갔습니다. 485는 첫날부터 이미 낮았고, 이는 용량이 작아 캐시 미스 비용 자체가 작다는 해석과 맞습니다. 다만 09-03 485는 NRU 178세션뿐이라 단정할 수 없습니다 — 09-05로 한 번 더 봐야 합니다.

폐기한 수치 — 이전 판에 실려 있던 값입니다

3D가 얹은 비용 +1,361ms · 압축이 되돌린 값 −1,195ms · 회수율 88% · 남은 차이 +166ms는 모두 날짜가 섞인 3군 비교에서 나온 값이라 조건을 맞추면 재현되지 않습니다. 실제 개선 폭은 위 표의 수백 ms 수준입니다.

477 대비는 판정할 수 없습니다

477은 09-02 하루치뿐이고 그날은 483 배포일이라, 그날 자체가 느린 날이었는지 걸러낼 대조군이 없습니다. 같은 09-02로 맞춰 보면 NRU p50은 477 5,173 vs 483 5,106(483이 빠름), RU는 4,197 vs 4,862(483이 665ms 느림)로 방향이 반대입니다 — 483의 09-02 표본이 NRU 164 · RU 495뿐인 것도 감안해야 합니다. 3D 페널티의 크기는 이 데이터로 확정할 수 없습니다.

갱신 쿼리

쿼리는 하나만 둡니다 — 판정 표 두 개와 서두 교차표가 모두 이 결과에서 나옵니다. WHERE log_date BETWEEN 한 줄만 고쳐 돌립니다. 29단계 곡선은 별도 쿼리에서 뽑았고, 그 전문은 커밋 7e1a22a 이전 판에 있습니다. DECLARE를 일부러 안 씁니다 — 상수를 선언하면 스크립트로 취급돼 실행 전 스캔 비용이 안 보입니다.

일자 × 빌드군 × NRU/RU 결승선 도달 시각 
-- 이 문서를 갱신할 때 돌리는 유일한 쿼리다. 위 판정 표 두 개와 서두의 일자 교차표가
-- 모두 이 결과에서 나온다. 결승선(1010)만 재므로 스캔도 가볍다.
-- ⚠ 빌드군을 곧바로 비교하지 마라. 빌드군은 일자와 붙어 있다 — 아래처럼 일자를 갈라 낸 뒤
--   ① 각 빌드의 "배포 다음 날"끼리, ② 같은 날 공존하는 두 빌드끼리만 비교한다.
-- 판정: 485 p50 이 일차마다 내려가고 483 이 평평하면 캐시 · 세 군이 같이 움직이면 그날의 회선
--      · 485 만 평평하거나 올라가면 캐시가 아니다(빌드 또는 유입 구성).
-- 조건은 곡선과 동일하다: country='US' · is_dev 제외 · 세션당 1행 · 10분 이상치 컷.
-- ⚠ 기간 = 아래 WHERE 의 날짜 두 개. 미래 날짜를 넣으면 파티션이 없어 0 B / 0행이다.
WITH src AS (
    SELECT
        log_date,
        CASE
            WHEN client_version >= 485              THEN '485+'
            WHEN client_version BETWEEN 483 AND 484 THEN '483~484'
            WHEN client_version <= 477              THEN '477-'
        END                                        AS grp,
        IF(logincount_total <= 1, 'NRU', 'RU')     AS seg,
        CONCAT(CAST(player_id AS STRING), '_', CAST(logincount_total AS STRING)) AS sk,
        CAST(JSON_VALUE(data, '$.time') AS INT64)  AS t,
        log_time
    FROM `game-log-359704.raw.solitaire_city_journey`
    WHERE log_date BETWEEN '2026-09-02' AND '2026-09-04'
      AND (is_dev = FALSE OR is_dev IS NULL)
      AND country = 'US'
      AND player_id > 0
      AND logincount_total IS NOT NULL
      AND event = '1010_LOAD_COMPLETE'
      AND JSON_VALUE(data, '$.time') IS NOT NULL
),
one AS (
    SELECT * FROM src
    WHERE grp IS NOT NULL AND t BETWEEN 0 AND 600000
    QUALIFY ROW_NUMBER() OVER (PARTITION BY sk ORDER BY log_time, t) = 1
)
SELECT
    seg                                    AS `구분`,
    grp                                    AS `빌드군`,
    log_date                               AS `일자`,
    COUNT(*)                               AS `세션`,
    CAST(ROUND(AVG(t)) AS INT64)           AS `평균_ms`,
    APPROX_QUANTILES(t, 100)[OFFSET(50)]   AS `p50_ms`,
    APPROX_QUANTILES(t, 100)[OFFSET(90)]   AS `p90_ms`
FROM one
GROUP BY 1, 2, 3
ORDER BY `구분`, `빌드군`, `일자`
전제 버전 경계 485+ / 483~484 / 477이하는 위 갱신 쿼리의 빌드군·일자 조합으로 확인하고 씁니다. 485가 100% 롤아웃되면 483 트래픽이 마르므로, 일자를 맞춘 비교는 09-03~04 창에서만 가능합니다 — 그 뒤로는 483을 배포 직전 창에서 따로 뽑아야 하고 기기·회선 구성 차이를 감안해야 합니다. data 스캔은 비용이 크므로 기간은 3~4일을 넘기지 않습니다.
