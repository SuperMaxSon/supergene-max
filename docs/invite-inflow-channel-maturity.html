⑤ 미해결 인용할 때 조심할 것

8/16 퍼블마 초대 유입을 "player_id + logincount_total 고유 세션"으로 세면 549인데 41 통합 pubma_inv_daily의 inv_in은 257입니다. 유입유저 229와도 맞지 않아 세션·유저 어느 정의도 아닙니다. 유입률 1.14% vs 2.55%는 양쪽에 같은 정의를 적용한 값이라 비교로는 유효하지만, "하루 몇 건 유입"이라는 절대값은 정의가 확정되기 전까지 인용하지 않습니다. → 41 페이지 작성 쿼리 확인 필요.

클리어의 2/3에서 슬롯이 안 뜨는 이유를 모릅니다

판당 소셜 슬롯 0.315는 클리어 3번 중 2번은 아무것도 안 뜬다는 뜻입니다. 그게 60초 쿨다운인지 "토너 컨텍스트가 아님"인지 구분할 로그가 없습니다(게이트 미노출 계측 갭). 그래서 쿨다운을 올려서 노출을 줄이겠다는 계획은 효과를 예측할 수 없습니다. 게이트별 미노출 로그를 먼저 추가하면 이 구분이 바로 끝납니다.

확인 범위 수치는 BigQuery 실측(8/16 하루 · 구간 지표는 41 통합 era_cmp 8/14~17)이고, 코드 대조는 solitaire-tripeaks와 block-blast(퍼블마) main 브랜치 직접 비교입니다. 추정으로 표시한 것: 채널 성숙도 가설 전체(②), C1~C3의 영향 크기. 측정하지 않은 것: D1~D5 전부, 우리 판 간격 분포.

D1 — 친구 수 분포 (우리 vs 퍼블마) 
WITH f AS (
  SELECT '솔' AS g, SAFE_CAST(JSON_VALUE(data, '$.friend_count') AS INT64) AS fc
  FROM `game-log-359704.raw.solitaire_city_journey`
  WHERE log_date = '2026-08-16' AND event = '6000_FRIEND_COUNT'
  UNION ALL
  SELECT '퍼블마', SAFE_CAST(JSON_VALUE(data, '$.friend_count') AS INT64)
  FROM `game-log-359704.raw.puzzle_block_master`
  WHERE log_date = '2026-08-16' AND event = '6000_FRIEND_COUNT'
)
SELECT
  g                                             AS `게임`,
  COUNT(*)                                      AS `세션`,
  ROUND(COUNTIF(fc = 0) * 100.0 / COUNT(*), 1)  AS `친구0명_pct`,
  APPROX_QUANTILES(fc, 100)[OFFSET(50)]         AS `p50`,
  APPROX_QUANTILES(fc, 100)[OFFSET(90)]         AS `p90`,
  ROUND(AVG(fc), 1)                             AS `평균_참고`
FROM f WHERE fc IS NOT NULL GROUP BY 1
평균이 아니라 p50과 0명 비율로 봅니다

WITH fc AS (

  FROM `game-log-359704.raw.solitaire_city_journey`
  WHERE log_date = '2026-08-16' AND event = '6000_FRIEND_COUNT'
  GROUP BY 1

inv AS (
  SELECT player_id,
         COUNTIF(event = '3460_MSG_P2P_INVITE')         AS try_cnt,
         COUNTIF(event = '3470_MSG_P2P_INVITE_SUCCESS') AS ok_cnt
  FROM `game-log-359704.raw.solitaire_city_journey`
  WHERE log_date = '2026-08-16'
    AND event IN ('3460_MSG_P2P_INVITE', '3470_MSG_P2P_INVITE_SUCCESS')
    AND JSON_VALUE(data, '$.position') = 'tournament_invite'

SELECT
  CASE WHEN f.friends = 0 THEN '0명'
       WHEN f.friends BETWEEN 1 AND 4 THEN '1~4명'
       WHEN f.friends BETWEEN 5 AND 19 THEN '5~19명'
       ELSE '20명+' END                                  AS `친구수_구간`,
  COUNT(DISTINCT i.player_id)                            AS `발신자`,
  SUM(i.try_cnt)                                         AS `시도`,
  SUM(i.ok_cnt)                                          AS `호출성공`,
  ROUND(SAFE_DIVIDE(SUM(i.ok_cnt), SUM(i.try_cnt)) * 100, 1) AS `호출성공률_pct`
FROM inv i JOIN fc f USING (player_id)
GROUP BY 1 ORDER BY 1
