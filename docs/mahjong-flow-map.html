마종 전체 지면 플로우 맵

솔리테어 · 코인 매치 플로우 맵과 같은 두 단 구조입니다. 1단 오픈맵으로 어느 지면이 어느 흐름에 있는지 보고, 2단 지면을 누르면 큰 팝업에 그 지면의 UI 와이어프레임(프리팹을 직접 파싱해 실제 버튼 좌표를 720×1280 세로 화면에 올린 그림)과 버튼별 한 줄 요약이 함께 뜹니다. 와이어프레임의 버튼이나 요약 셀을 누르면 그 자리에서 호출 흐름이 아래로 펼쳐집니다. 맵은 세로 스파인입니다 — 가운데 줄기가 한 판의 진행 순서(부팅 → 진입 라우팅 → 로비 → 인게임 → 결과 정산 → 판 종료 후 5단계)이고, 왼쪽 레일은 그 단계에서 새어 나가는 길, 오른쪽 레일은 그 단계가 여는 지면입니다. 띠 5개가 세로 눈금이라 위에서 아래로만 훑으면 한 판이 끝납니다. 찾는 게 정해져 있으면 오른쪽 위 검색창(단축키 /)에 메소드명 · 지면 이름 · 프리팹 · 버튼 라벨을 치면 그 지면을 열고 접힘까지 펼쳐서 보여줍니다.

이 그림이 어디서 나왔나

손으로 그린 그림이 아닙니다. 번들 프리팹을 파싱해 _trs 좌표와 cc.Widget 정렬을 계산한 결과입니다. 생성기는 mahjong-client/_ignore/flowmap/ 에 있고, 솔리테어 → 코인 매치로 이어져 온 생성기를 이 프로젝트로 이식한 것입니다. 회전은 무시했고, 프리팹 저장 시점 비활성 장식 · 화면 밖 스크롤 컨텐츠 · 잠금 오버레이는 뺐습니다. 반복 셀 93개는 대표 1개 + ×n 으로 접었고, 부모와 같은 자리를 차지하는 중복 상자 167개는 지웠습니다.

정규화 기준은 부팅 씬 intro.fire 의 cc.Canvas._designResolution (720×1280)입니다. settings/project.json 값이 아닙니다 — 코인 매치는 거기가 960×640 인데 실제 캔버스는 720×1280 이라 그 값으로 재면 좌표가 전부 어긋납니다.

비활성 버튼을 왜 남겼나

프리팹의 _active = false 는 “에디터에 파킹”이 아니라 대개 런타임 조건부 노출입니다. 같은 지면에 활성본이 따로 있을 때만 버렸고 (이번에 68개), 그 핸들러로 갈 길이 이것뿐이면 남겨 점선으로 그립니다. 함부로 버리면 조건부로만 뜨는 버튼이 통째로 사라집니다.

로비에 탭이 없다 — 코지와 갈리는 지점 — 상점 · 도감 · 친구 · 토너먼트가 각각 독립 View 프리팹이고 번들도 assets/bundles/lobby/{shop,collection,friends,tournament} 로 따로다. 로비 진입 시점에 같이 받지 않고 각 지면을 처음 열 때 받는다.

확인 버튼 경로가 두 벌로 복사돼 있다 — onClickConfirmButton() 은 전면광고 유무로 같은 코드가 두 번 적혀 있다(1011~1033 과 1034~1055). 한쪽만 고치면 광고가 나간 유저와 안 나간 유저의 동작이 갈린다.

솔로 복귀 호출부가 19곳 — Fbi.switchToContextSolo() 호출부가 코지(8곳)의 2배가 넘는다. 컨텍스트를 되돌리는 지점이 그만큼 흩어져 있다.

결과 화면에 A/B 두 벌이 들어 있다 — isATest 에 따라 같은 프리팹의 ANode / BNode 중 하나만 켠다.
