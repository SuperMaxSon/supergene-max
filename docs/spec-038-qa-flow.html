SPEC-038 토너 초대 토글 — QA 가이드

토너 판을 깰 때마다 공유 다이얼로그만 뜨던 것을, 초대 → 공유 → 초대 → 공유로 번갈아 뜨게 바꿨습니다.

솔리테어 · FB 인스턴트 dev 빌드 2026-08-13 15:06 개정

판정 흐름도 판을 깬 순간 위에서부터 순서대로 걸러집니다

"안 뜨는 게 정상"인 경우가 둘 있습니다

누적 승수 4 미만과 60초 이내 재클리어는 공유·초대 어느 쪽도 뜨지 않는 것이 정상입니다. 다이얼로그가 안 떴다면 이슈로 올리기 전에 이 두 가지부터 확인해 주세요. 반대로 기능이 꺼져 있을 때(밸런스 시트 상수 10108 = 0)와 이미 종료된 토너먼트에서는 예전처럼 공유가 반드시 떠야 합니다.

준비

항목 내용
빌드 FB 인스턴트 dev 빌드 (에디터 프리뷰에서는 토너 기능이 동작하지 않습니다)
실행 방법 아이콘 · 토너 링크 어느 쪽이든 됩니다. 아이콘으로 켠 뒤 로비에서 토너먼트에 참가해도 동일하게 동작합니다
차례 확인 · 변경 브라우저 콘솔에서 아래 명령 (다음 차례를 초대/공유로 강제 지정)
콘솔 명령 펼치기 
// 지금 차례 확인
// true = 다음은 초대 / false = 다음은 공유 / null = 아직 한 번도 안 뜬 상태(다음은 초대)
localStorage.getItem("tournamentInviteNext");

// 다음 차례를 "초대"로 지정
localStorage.setItem("tournamentInviteNext", "true");
location.reload();

// 다음 차례를 "공유"로 지정하려면 "true" 자리에 "false"
페이스북 플레이어 데이터가 아니라 브라우저 저장소입니다

이 값은 브라우저 localStorage에 저장됩니다. FBInstant.player.getDataAsync로 찾으면 나오지 않습니다. 시크릿 모드처럼 localStorage가 막힌 환경에서는 페이스북 저장소에 대신 저장되는데, 그때는 위 명령이 듣지 않으니 일반 창에서 테스트해 주세요. 또 기기나 브라우저가 바뀌면 차례가 초기화되어 초대부터 다시 시작하는데, 이것도 정상 동작입니다.

A. 기본 동작 진행 중인 토너먼트에 들어간 뒤, 위에서부터 끊지 말고 순서대로

순서 이렇게 하면 이래야 정상
A-1 차례를 초대로 지정하고 판 클리어 초대 다이얼로그가 뜬다 → 전송
A-2 곧바로(60초 안) 한 판 더 클리어 아무것도 안 뜬다
A-3 60초 지난 뒤 한 판 더 클리어 공유 다이얼로그가 뜬다 (차례가 넘어갔으므로)
A-4 60초 지난 뒤 클리어 → 초대창을 그냥 닫기 초대 다이얼로그가 떴다가 닫힌다
A-5 60초 지난 뒤 한 판 더 클리어 공유가 뜬다 (취소해도 차례는 넘어감)
A-6 앱을 완전히 껐다 켜고 60초 뒤 클리어 껐을 때의 차례가 그대로 이어진다 (초기화되지 않음)
A-2와 A-5가 이 기능의 핵심

A-2는 60초 안에 또 뜨지 않는지, A-5는 초대를 취소해도 다음 판이 공유로 넘어가는지를 봅니다. 둘 중 하나라도 어긋나면 바로 이슈로 올려 주세요.

B. 안 떠야 하는 경우 각각 따로 실행

순서 이렇게 하면 이래야 정상
B-1 이미 끝난 토너먼트 컨텍스트에서 판 클리어 항상 공유만 뜬다. 초대는 절대 안 뜬다
B-2 새 계정(누적 승 0)으로 토너 판 3번 클리어 세 번 모두 아무것도 안 뜬다. 4승째부터 뜨기 시작한다
B-3 기능을 끈 상태(개발자에게 요청)로 토너 판 클리어 예전처럼 공유만 뜬다. 60초 제한도 없다
B-2의 기준은 "누적 승수" 하나입니다

코드상 차단 조건은 누적 승 4 미만 그리고 튜토리얼 미완료지만, 튜토리얼 완료 표시는 레벨 25가 되어야 켜집니다. 4승 미만 구간에서는 튜토리얼이 항상 미완료라, 결국 누적 승수만 보면 됩니다. 로비에 표시되는 레벨 숫자가 곧 누적 승수이니 그 값이 4 이상인지로 판단해 주세요.

B-3이 제일 중요합니다

문제가 생겼을 때 되돌리는 유일한 방법이 기능 끄기입니다. 껐을 때 예전 동작으로 완전히 돌아가지 않으면 라이브에서 되돌릴 수단이 없습니다. 개발자에게 요청해서 한 번은 꼭 확인해 주세요.

C. 기존 기능이 그대로인지 이번에 건드리지 않았지만 옆에 있는 것들

순서 이렇게 하면 이래야 정상
C-1 일반(비토너) 판 클리어 기존 토너 만들기 다이얼로그가 그대로 뜬다
C-2 토너 판을 중간에 나가기 아무것도 안 뜨고, 다음 판 차례도 그대로다
C-3 레벨 진입 · 우편함 · 레벨 완료 화면에서 친구 초대 초대가 기존대로 정상 동작한다
C-4 B-2(누적 승 4 미만, 아무것도 안 뜸) 상태에서 클리어 후 토너 순위 확인 다이얼로그가 안 떠도 내 점수는 올라가 있어야 한다
C-4를 빠뜨리지 마세요

다이얼로그를 막는 처리와 점수를 서버에 올리는 처리가 붙어 있어서, 잘못 구현하면 "팝업이 안 뜨는 판은 점수도 안 올라가는" 문제가 생깁니다. 눈에 잘 안 띄지만 영향은 가장 큰 항목입니다.

D. 로그 · 유입 확인 NEW 08-13 12:27 화면은 정상인데 로그가 틀리면 지표를 못 읽습니다 — 개발자 도구 필요

항목 내용
확인 방법 크롬 개발자 도구 → Network 탭에서 game-log 로 필터. 각 요청의 Payload에 event(이벤트 이름)와 data(파라미터)가 들어 있습니다
보는 이벤트 3460_MSG_P2P_INVITE(초대창 뜸) · 3470_MSG_P2P_INVITE_SUCCESS(전송 완료) · 3480_MSG_P2P_INVITE_FAIL(취소 · 실패)
순서 이렇게 하면 이래야 정상
D-1 A-1처럼 초대 다이얼로그가 뜬 순간 3460이 1건. position이 "tournament_invite", image_id가 "invite"
D-2 그 초대창에서 전송 완료 3470이 1건. position은 D-1과 동일
D-3 초대창을 취소 · 그냥 닫기 (A-4) 3480이 1건. position 동일 + error_code가 "USER_INPUT"
D-4 공유 차례에서 판 클리어 (A-3) 3460은 안 나가고 3200_TOURNAMENT_SHARE만 나간다
D-5 받은 초대 링크로 다른 계정이 게임 진입 (수신 측 · 계정 2개 필요) 1000_LOGIN_COMPLETE의 entrypoint.payload.social이 "TOURNAMENT_INVITE"
D-6 D-5와 같은 진입에서 인트로 로딩 시간을 본다 (아이콘으로 켰을 때와 비교) 아이콘 진입과 비슷하게 로딩된다. 눈에 띄게 오래 멈춰 있으면 이슈
D-1에서 position이 숫자면 바로 이슈입니다

"tournament_invite" 같은 이름이 아니라 "0" · "1" 같은 숫자 문자열로 찍히면, 초대가 어느 지면에서 나갔는지 나중에 구분할 수 없습니다. 같은 실수가 기존 메시지 로그(3400 계열)에 이미 있어서 특히 주의해서 봐야 하는 항목입니다.

D-5를 콘솔로 더 빠르게 확인하기 
// 초대 링크로 들어온 직후, 수신 계정의 브라우저 콘솔에서
FBInstant.getEntryPointData();
// → { social: "TOURNAMENT_INVITE", feed: "INVITE", is_invite: true, ... } 여야 정상
초대로 들어온 유저가 토너먼트 화면으로 가는 것은 정상입니다

초대 유입도 토너 진입 분기를 그대로 탑니다. 초대를 받아 들어온 사람이 그 토너먼트로 바로 들어가야 초대가 이어지기 때문에 의도한 동작입니다. social 값만 TOURNAMENT_INVITE인지 확인해 주세요 — 토너 공유로 들어오면 TOURNAMENT입니다.

D-6은 계정 2개를 세팅한 김에 꼭 같이 봐 주세요

초대로 들어온 세션은 토너먼트 조회를 기다리는 경로를 함께 탑니다. 그런데 초대는 대화방(스레드) 컨텍스트라 기다릴 토너먼트가 아예 없을 수 있고, 그러면 인트로에서 불필요하게 멈춰 있게 됩니다. 아직 실기기에서 한 번도 확인되지 않은 항목이라, 수신 측 테스트를 하는 김에 로딩 체감만 같이 봐 주시면 됩니다.

다른 지면 초대에서도 3460이 찍히는 것은 정상입니다

C-3(레벨 진입 · 우편함 · 레벨 완료)에서 친구를 초대해도 이제 3460이 나갑니다. 그동안 계측이 없던 지면들이라 이번 빌드부터 함께 수집되는 것으로, 이때는 position이 invite_level_entry · invite_mail · invite_level_complete로 찍힙니다.

기획서와 다른 점 아래 2가지는 의도된 차이입니다 — 결함이 아닙니다

기획서 문구와 실제 구현이 어긋나는 부분은 이미 라이브에서 돌고 있는 퍼블리싱 마스터 쪽에 맞췄습니다. 기획서만 보고 테스트하면 아래가 어긋난 것처럼 보입니다.

  • 첫 차례가 공유가 아니라 초대입니다
  • 누적 승 4 미만 계정은 공유·초대 어느 쪽도 안 뜹니다 (B-2)
"취소해도 차례가 넘어간다"는 기획서에도 반영됐습니다

기획서 최신판에 차례를 뒤집는 기준 = 다이얼로그가 뜬 것 (유저 취소 포함)으로 명시돼 있어, 더 이상 차이 항목이 아닙니다. A-4 · A-5는 기획서대로 동작하는지를 보는 항목으로 그대로 진행해 주세요.

이 2가지는 이슈로 올리지 말아 주세요

위 2가지는 기획서와 다르게 동작하는 것이 정상입니다. 반대로 여기에 없는 기획서 불일치를 발견하면 올려 주세요 — 의도한 차이가 아닐 수 있습니다.

이건 버그입니다

증상 어긋난 항목
초대만 계속 뜨고 공유가 한 번도 안 뜬다 A-3 · A-5 (차례가 안 넘어감)

다이얼로그가 안 뜬 판의 토너 점수가 안 올라간다 C-4 (최우선)
